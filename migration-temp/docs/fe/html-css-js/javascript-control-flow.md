## 1. 자바스크립트 제어 흐름

### 1.1 자바스크립트 비동기

- 자바스크립트는 다른 멀티스레드 언어(Java, C++)와 다른 방식으로 비동기 동작을 처리
- 코드를 순서대로 실행하는 것이 아니라, 함수 호출이 일어나면 그곳으로 코드가 실행됨 (예: `setTimeout`)
- **자바스크립트 엔진**: 하나의 메인 스레드로 구성. 메인 스레드가 코드를 한 줄씩 읽어 실행. 브라우저 환경에서는 유저 이벤트 처리·화면 그리기도 담당

### 1.2 동기적 제어 흐름

- 현재 실행 중인 코드가 종료되기 전까지 다음 줄을 실행하지 않음
- 분기문, 반복문, 함수 호출 등이 동기적으로 실행
- **코드의 흐름과 실제 제어 흐름이 동일**
- 싱글 스레드 환경에서 메인 스레드를 긴 시간 점유하면 프로그램이 멈춤

### 1.3 비동기적 제어 흐름

- 현재 실행 중인 코드가 종료되기 전에 다음 라인을 실행
- Promise, 콜백 함수를 호출하는 함수 등이 비동기적으로 실행
- **코드의 흐름과 실제 제어 흐름이 다름**
- 비동기 작업을 기다리는 동안 메인 스레드는 다른 작업을 처리
- 자바스크립트 엔진은 비동기 처리를 직접 제공하지 않지만, 정해진 함수를 제공해 활용 → **API**
  - 예: `setTimeout`, `XMLHttpRequest`, `fetch` 등의 Web API

## 2. 이벤트 루프

- 자바스크립트 엔진 외부에 존재. Node.js 환경의 경우 **libuv** 모듈에서 비동기 처리 담당
- 콜 스택이 비워지는 것을 기다린 후 task 큐에서 콜백 함수를 꺼냄
- 비동기 처리가 끝나면 task 큐에 콜백 함수가 들어감
- task 큐는 들어온 순서대로 콜백 함수를 내보냄

## 3. Promise

- **Promise API**: 비동기 API
- 태스크 큐가 아닌 **잡 큐(Job Queue, microtask queue)** 를 사용
- 잡 큐는 태스크 큐보다 **우선순위가 높음**
- 비동기 작업을 표현하는 자바스크립트 객체
- 비동기 작업의 진행, 성공, 실패 상태 표현

| 상태 | 설명 |
|---|---|
| `pending` | 진행 중 (예: `fetch(...)` 호출 직후) |
| `fulfilled` | 성공 |
| `rejected` | 실패 |

- 비동기 처리의 순서를 표현할 수 있음

## 4. async / await

Promise를 활용한 비동기 코드를 간결하게 작성하는 문법.

- async/await로 비동기 코드를 동기 코드처럼 간결하게 작성 가능
- `async` 함수와 `await` 키워드를 사용
- **`await` 키워드는 반드시 `async` 함수 안에서만** 사용
- `async`로 선언된 함수는 반드시 **Promise를 리턴**

## 5. HTTP, REST API

### 5.1 HTTP

**HTTP** (HyperText Transfer Protocol): 웹에서 서버와 클라이언트 간 통신 방법을 정한 것.

- **클라이언트**: 웹 브라우저 등 서버로 요청을 보내는 대상
- **서버**: 클라이언트의 요청 전까지 대응하지 않음
- 서버와 클라이언트 사이에는 무수히 많은 요소 존재
- HTTP는 이런 존재들 사이의 통신 방법을 규정

### 5.2 HTTP Message

- 서버 주소, 요청 메서드, 상태 코드, target path, 헤더 정보, 바디 정보 등이 포함
- 요청 메시지·응답 메시지 모양이 다름
- HTTP/1.1 메시지는 사람이 읽기 어려움

### 5.3 HTTP Header

- 콘텐츠 정보, 인증 정보, 쿠키, 캐시 등 서버-클라이언트 통신에 필요한 정보를 담음
- 클라이언트 요청·서버 응답 모두 헤더에 정보 포함 가능

### 5.4 HTTP Status

- HTTP 요청 시 클라이언트는 결과에 대한 상태 정보를 받음
- 200, 400, 500 등 숫자 코드 + `OK`, `NOT FOUND` 같은 텍스트
- 코드를 이용해 결과별 행위를 수행

### 5.5 요청 메서드

| 메서드 | 의미 |
|---|---|
| `GET` | 리소스 정보 조회 |
| `POST` | 리소스 생성 |
| `PUT` | 리소스 생성 또는 업데이트 |
| `PATCH` | 리소스 부분 수정 |
| `DELETE` | 리소스 제거 |
| `OPTIONS`, `CONNECT`, `TRACE` | 등 |

### 5.6 REST API

- **API** (Application Programming Interface): 사용자가 특정 기능을 사용할 수 있도록 제공하는 함수
- **REST API** (Representational State Transfer API): HTTP 요청 메서드에 응하는 서버 API와 클라이언트 간 통신 구조가 지켜야 할 좋은 방법을 명시한 것
- 구체적 내용: 요청 메서드의 의미, URI 설계, 클라이언트 상태에 대한 동작 등
