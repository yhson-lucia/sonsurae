## 1. 이상 현상 (Anomaly)

잘못된 DB 설계로 발생하는 오류.

| 종류 | 설명 | 예 |
|---|---|---|
| **삽입 이상** | 데이터 삽입 시 불필요한 내용까지 삽입해야 하는 문제 | 주문하지 않은 고객 데이터를 넣을 수 없는 문제 |
| **갱신 이상** | 중복된 데이터 중 일부만 갱신되어 불일치 발생 | 고객 주소 수정을 위해 모든 튜플에서 갱신해야 하는 문제 |
| **삭제 이상** | 어떤 데이터를 삭제할 때 다른 유용한 정보도 함께 삭제 | 회원의 주문 기록을 지우려면 회원 데이터까지 삭제되는 문제 |

## 2. 함수 종속성

속성들 간의 종속 관계.

- 어떤 속성 X의 한 값이 다른 속성 Y의 하나의 값에만 매핑되는 경우
- X = **결정자**, Y = **종속자** (예: ID → 이름)
- 종류: **완전 함수 종속**, **부분 함수 종속**, **이행 함수 종속** 등
- 함수 종속성을 알아야 정규화를 이해할 수 있음

## 3. 정규화 (Normalization)

이상 현상을 제거하기 위해 데이터베이스를 구조화하는 과정.

- 데이터 간 종속성을 제거해 중복을 줄임
- 데이터의 일관성과 무결성 보장
- 단계: 1차 / 2차 / 3차 / BCNF / 4차(특수) / 5차(특수)

### 3.1 1차 정규화 (1NF, Normal Form)

- 테이블의 컬럼이 **하나의 값만 갖도록** 도메인을 원자값으로 설정

### 3.2 2차 정규화 (2NF)

- **부분 함수 종속을 제거**하고 완전 함수 종속이 되도록 테이블을 분해
- 기본키를 구성하는 속성 중 일부가 결정자 역할을 하는 경우
- 기본키가 복합키이거나 후보키가 결정자인 경우 부분 함수 종속이 발생할 수 있음
- 반대로 기본키 모든 속성이 결정자인 경우는 **완전 함수 종속**

### 3.3 3차 정규화 (3NF)

- **이행 함수 종속을 제거**하도록 테이블을 분해
- **이행 함수 종속**: X → Y, Y → Z일 때 X → Z가 성립하는 경우
  - 즉, X로 Y를 알고, Y로 Z를 알 수 있는 관계

### 3.4 BCNF (Boyce-Codd Normal Form)

- **결정자이면서 후보키가 아닌 것**을 제거

## 4. 역정규화 (Denormalization)

정규화된 DB의 성능을 개선하기 위해 다시 통합하여 구조를 재구성.

- 정규화로 테이블을 분해하면 여러 테이블 조인 시 성능이 떨어질 수 있음
- 자주 사용되는 쿼리를 고려해, **데이터 중복을 감안하고 역정규화**하는 것이 효율적일 수 있음
