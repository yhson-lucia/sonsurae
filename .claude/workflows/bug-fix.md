# 워크플로우: 버그 수정

> 트리거: `/quick-fix` 슬래시 커맨드 또는 "X 버그 고쳐줘"

## 목적
근본 원인을 해결하고 재발을 방지하는 체계적 버그 수정.

## 흐름도

```
[버그 신고]
    ↓
[증상 재현 및 정리]
    ↓
Explore (관련 코드 검색)
    ↓
[근본 원인 식별]
    ↓
적절한 에이전트 호출
(ui-designer / db-architect / 직접 수정)
    ↓
┌────┴────┐
↓         ↓
code-rev  sec-aud      (병렬 검증)
└────┬────┘
     ↓ (통과)
test-writer (회귀 테스트)
     ↓
docs-writer (트러블슈팅 기록)
     ↓
[수정 완료 보고]
```

## 핵심 원칙

### 1. 증상 ≠ 원인
- 표면 증상이 아닌 근본 원인 수정
- 같은 패턴의 다른 버그 가능성 확인

### 2. 회귀 방지 필수
- 수정 후 반드시 테스트 추가
- 같은 버그가 재발하지 않도록

### 3. 학습 누적
- 모든 버그는 `docs/troubleshooting/`에 기록
- 학습 포인트 추출 → 컨벤션/가이드로 승격

## 단계별 체크리스트

- [ ] 재현 시나리오 명확화
- [ ] 관련 코드 탐색 (Explore)
- [ ] 근본 원인 식별
- [ ] 영향 범위 파악
- [ ] 수정 코드 작성
- [ ] code-reviewer 검증
- [ ] security-auditor 검증 (인증/권한 관련 시)
- [ ] 회귀 테스트 작성
- [ ] **docs/system/* 동기화** (수정된 파일별 매핑표 따름)
- [ ] 트러블슈팅 문서 작성
- [ ] 사용자에게 수정 내용 보고

## 트러블슈팅 문서 템플릿

```markdown
# [문제 제목]

## 증상
- 사용자가 본 증상
- 에러 메시지 (있다면)

## 재현 시나리오
1. ...
2. ...

## 근본 원인
[표면 증상이 아닌 진짜 원인]

## 해결 방법
[코드 변경 또는 설정 변경]

## 학습 포인트
[다음에 어떻게 예방할지]

## 관련 변경
- 커밋: [해시]
- PR: [링크]
- 추가된 테스트: [파일]
```
