# 🔍 종합 검증

다음 대상을 모든 검증 에이전트로 검토합니다: **$ARGUMENTS**

대상이 명시되지 않으면 `git diff`로 변경된 모든 파일을 검토합니다.

## 작업 순서

### 1. 변경 범위 파악
- `$ARGUMENTS`가 비어있으면 `git diff --name-only` 실행
- 변경 파일 목록 확보

### 2. 검증 에이전트 병렬 실행

다음 3개 에이전트를 **반드시 병렬로** 호출 (single message에 multiple tool calls):

1. **code-reviewer agent**
   - 보안, 정확성, 성능, 컨벤션, 가독성

2. **security-auditor agent**
   - OWASP Top 10
   - 환경변수 노출
   - RLS 검증

3. **seo-optimizer agent** (페이지/메타데이터 변경 시)
   - 메타태그
   - 구조화 데이터
   - 시맨틱 HTML

### 3. 결과 통합 보고

각 에이전트 결과를 표로 정리:

```markdown
## 🔍 종합 검증 결과

### 검토 대상
- 파일 1
- 파일 2

### 종합 점수
| 에이전트 | 결과 | 핵심 이슈 |
|---------|------|----------|
| code-reviewer | 🟢 / 🟡 / 🔴 | ... |
| security-auditor | 🟢 / 🟡 / 🔴 | ... |
| seo-optimizer | 🟢 / 🟡 / 🔴 | ... |

### 🔴 Critical (즉시 수정)
- [통합된 critical 이슈]

### 🟠 High (수정 권장)
- [통합 이슈]

### 🟡 Medium (개선 권장)
- [통합 이슈]

### 🎯 종합 판단
- 머지 가능 / 수정 후 머지 / 재작업 필요
```

### 4. 수정 제안
Critical/High 이슈는 구체적인 수정 코드 제시

## 사용 시점
- PR 생성 전
- 큰 리팩토링 후
- 배포 전 최종 점검
- 보안 민감 코드 변경 후

## 주의사항
- **반드시 병렬 호출** (각각 따로 호출하면 비효율)
- 에이전트 간 의견 충돌 시 우선순위: 보안 > 정확성 > 성능 > SEO
